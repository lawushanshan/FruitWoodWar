# 城堡战争：果林大战 —— 开发排障记录

> 本文档记录开发过程中已经解决的关键问题，便于后续遇到同类现象时快速回溯。

---

## 2026-08-20：预览页打开后没有渲染画面

### 现象

- Cocos Creator 预览地址 `http://localhost:7456/` 可以打开，但页面看不到游戏 UI。
- 场景与脚本能够加载，`cc` 全局对象存在，游戏并不是完全启动失败。

### 排查过程

1. 通过 Cocos MCP 检查场景结构，发现 `GameManager` 挂在 `Canvas/Camera` 子节点上。
2. 阅读 `assets/scripts/GameManager.ts`，确认脚本在初始化时大量依赖 `this.node.layer`：
   - `this.uiLayer = this.node.layer`
   - `GameContainer`、`UIContainer`、按钮、文字等动态节点都会继承 `this.uiLayer`
3. 对比场景结构后确认：脚本设计上假设 `this.node` 是 `Canvas`，这样才能拿到 UI 渲染层。
4. 通过 BrowserOS neo 打开前台预览页验证，同时用 Cocos MCP 调用 `onStartClick({})`，逻辑可以进入 `playing` 阶段并创建建筑，说明游戏逻辑正常，问题集中在渲染层。

### 根因

`GameManager` 被挂载在 `Canvas/Camera` 节点上。动态创建的 UI 继承了 Camera 节点的 layer，而 UI 相机不渲染该 layer，导致页面表现为空白或黑屏。

### 解决方案

在 `assets/scenes/game.scene` 中把 `GameManager` 组件从 `Canvas/Camera` 移到 `Canvas`：

- 修复前：`Canvas/Camera` 挂载 `GameManager`
- 修复后：`Canvas` 挂载 `GameManager`

修复后动态 UI 会继承 Canvas 的 UI 渲染层，可以被 UI 相机正常渲染。

### 验证结果

- 预览页场景加载为 `game`。
- `Canvas` 下包含 `GameContainer`、`UIContainer`、`Camera`。
- `Canvas` 组件列表中存在 `GameManager`。
- 直接调用 `onStartClick({})` 后：`gameRunning=true`、`phase=playing`、`buildings=2`。
- `npm test`：10 个测试全部通过。
- `npm run typecheck`：通过。

### 备注

Cocos 预览页在浏览器后台标签页中可能不会完成场景生命周期初始化，表现为 `cc.director.getScene()` 为 `null`。验证预览效果时需要把 `http://localhost:7456/` 标签页切到前台，再刷新页面。

### 后续约定

- `GameManager` 必须挂载在 `Canvas` 根节点上，不要挂到 Camera 或其他动态 UI 容器上。
- 新增动态 UI 节点时继续显式设置 `node.layer = this.uiLayer`，避免依赖默认 layer。
- 如果预览页空白，先检查浏览器标签页是否在前台，再检查节点树、组件挂载位置和 UI 相机 visibility。
