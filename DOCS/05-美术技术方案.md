# 城堡战争：果林大战 —— M3 美术技术方案

> 版本：v1.0 ｜ 日期：2026-08-23 ｜ 依据：《01-玩法设计总纲》《03-开发落地路线图》
>
> 目标：完成 M3 里程碑验收标准——**Q 版美术替换完成、三阵营一眼可区分、打击感到位**。
>
> 本方案基于 2026 年 8 月对 AI 美术工具、2D 动画方案、小游戏包体限制的调研得出。

---

## 1. 决策结论（先说答案）

**主路线：AI 生成静态立绘 + 程序动画（tween 补间），不做逐帧动画、不上 Spine 骨骼动画。**

| 决策项 | 选择 | 一句话理由 |
|---|---|---|
| 素材来源 | **AI 生成**（主力：即梦 AI；辅助：豆包、Nano Banana） | 免费、国内直连、中文提示词、卡通风格是 AI 最稳的领域 |
| 动画方式 | **程序动画**（1 张静态图 + 代码补间） | 同屏最多 120 个单位，骨骼/逐帧动画在小游戏低端机上跑不动 |
| UI 底板 | Kenney UI Pack（CC0 免费）打底 + AI 图标 | UI 通用件用成熟素材最稳，图标用 AI 保持风格统一 |
| 兜底方案 | Kenney Tiny 系列整套替换 | 如果 AI 风格实在统一不了，CC0 素材随时可回退 |
| 不选择 | Midjourney（$30/月+海外支付）、Spine（$99+性能风险）、人工外包（贵） | 见第 2 节对比 |

## 2. 方案对比（为什么这么选）

### 2.1 素材来源五条路线对比

| 路线 | 成本 | 风格统一性 | 三阵营定制 | 适合本项目 | 主要风险 |
|---|---|---|---|---|---|
| A. AI 生成（即梦/豆包，免费档） | ¥0 | ★★★★（靠参考图法） | ★★★★★（15 兵种随便定制） | ✅ **推荐** | 风格漂移、抠图边缘 |
| B. AI 生成（Midjourney） | ~$30/月 | ★★★★★ | ★★★★★ | ❌ | 海外支付、无透明背景输出、公开画廊泄密 |
| C. AI 生成（本地 Stable Diffusion + LoRA） | ¥0（需 16GB+ 显存显卡） | ★★★★★（LoRA 锁死） | ★★★★★ | ⚠️ 备选 | 学习曲线 40+ 小时，硬件门槛 |
| D. 免费素材站（Kenney / itch.io） | ¥0 | ★★★★★（包内统一） | ★★（找不到"西瓜壮汉"这种定制主题） | ⚠️ UI/兜底用 | 无法体现 15 原创兵种 |
| E. 人工外包 | 每张 ¥50~300 | ★★★★★ | ★★★★★ | ❌ | 超预算 |

**结论**：本游戏的 15 个兵种（西瓜壮汉、老橡树守卫、犀牛铁卫……）是原创 IP，免费素材站不可能有现成的；AI 生成对"Q 版卡通"这类风格恰好最稳定；开发者在国内、预算为零，即梦/豆包每天有免费积分。**选 A，用 D 兜底**。

### 2.2 动画三方案对比（关键决策）

| 方案 | 资源量 | 性能（同屏多单位） | 制作成本 |
|---|---|---|---|
| Spine/Live2D 骨骼动画 | 最小（部件+json） | **最差**（每帧计算骨骼） | 高（软件收费+学习） |
| 逐帧序列动画 | 大（每动作 8~12 张） | 好 | 中（AI 多帧一致性难） |
| **程序动画（tween）** | **最小（每单位 1 张图）** | **最好**（只是位移/缩放/旋转） | **低（纯代码） |

依据：
- 本作人口上限每方 60、双方同屏最多 **120 个单位**，且 M4 要求"低端机 30 帧稳定"；
- Cocos 社区实测：600 个动画实例，帧动画 60 帧 vs Spine 仅 21 帧——多单位场景公认"帧动画/程序动画优先"；
- Q 版卡通 + 全龄化风格（弹跳、挤压拉伸）天然适合程序动画表现；
- 现有代码已有 tween、弹道、粒子基础（`spawnEffect`/`updateEmojiVisual`），改造成本最低。

## 3. 统一美术规范（风格锚点）

> 所有素材必须遵守同一套规范，这是"看起来像一个游戏"的根基。

### 3.1 全局风格关键词（每条提示词都带）

```
Q-version cartoon game art, chibi proportions (2 heads tall body), thick clean outlines,
flat cel shading with soft shadow, bright candy colors, cute and friendly,
mobile casual game style, full body, side view, centered composition,
isolated on solid green background (#00FF00),
no text, no watermark, no ground shadow, no extra objects
```

反向提示词（负面词，防崩坏）：

```
blurry, realistic, photo, scary, dark, blood, thin body, text, watermark,
multiple characters, cropped limbs, perspective distortion, gradient background
```

> 说明：**纯绿背景**是为抠图准备的（绿幕原理，比白背景抠得干净）；`side view` 侧面视角匹配本作横向战场。

### 3.2 三阵营色板（阵营识别的第一要素）

| 阵营 | 主色 | 辅色 | 氛围关键词（提示词附加） |
|---|---|---|---|
| 🍉 水果王国 | 橙红 `#FF7043` | 果绿 `#8BC34A`、柠檬黄 `#FFEB3B` | juicy, fruity, glossy, sunshine |
| 🌳 绿木林 | 森绿 `#2E7D32` | 木棕 `#8D6E63`、叶亮绿 `#66BB6A` | forest, woody, leafy, mossy |
| 🦁 动物庄园 | 琥珀黄 `#FFCA28` | 皮棕 `#A1887F`、奶白 `#FFF8E1` | furry, wild, safari, warm |

红蓝双方区分：同阵营单位在敌我两侧时，脚底加红/蓝小圆环（程序绘制，已有色块机制可直接做），不靠改贴图。

### 3.3 阵营一致性锚点流程（防"越生成越走样"）

1. 先集中一次生成每阵营 1 张「全家福标准图」（该阵营 5 个兵种同框）；
2. 全家福定稿后保存，作为该阵营所有后续生成的**参考图**（即梦参考强度 85%~100%）；
3. 之后单个资产生成时：提示词 = 全局风格关键词 + 阵营氛围词 + 主体描述，并挂对应阵营参考图；
4. 三段式结构：`[身份锚点：它是谁] + [动作/姿态] + [风格约束]`，每次只改一个变量；
5. 每张定稿记录：提示词 + 参考图 + 参数，存 `DOCS/美术生产记录.md`（后续补图不跑偏）。

## 5. 生产管线（从提示词到进游戏，6 步 SOP）

```
① 写提示词（模板+参考图） → ② 即梦批量生成（每张出4选1） → ③ 抠图去底
→ ④ 批量裁切缩放命名（Python 脚本） → ⑤ 放入 assets/resources/art/ 自动图集
→ ⑥ 代码接入替换 emoji
```

### 5.1 各类资产提示词模板（在 3.1 全局词基础上追加）

**兵种单位**（示例：西瓜壮汉）：

```
[主体] a round chubby watermelon warrior wearing a watermelon-rind helmet,
holding a big wooden mallet with both hands, happy determined smile
[阵营] juicy fruity orange-red color scheme
```

| 定位 | 主体描述要点 |
|---|---|
| tank 坦克 | 圆滚滚体型大一号、盾牌/铠甲、稳重表情 |
| ranged 远程 | 瘦一点、弓/弹弓/投掷物、瞄准姿势 |
| aoe 法师 | 袍子/法杖、头顶发光物、得意表情 |
| rush 冲锋 | 前倾冲刺姿态、轻装、速度线 |
| siege 攻城 | 推着小车/投石机、慢重、体型最宽 |

**大本营**（示例：黄金菠萝王座）：`a majestic golden pineapple throne crystal base, glowing, ...  front view`
**兵工厂**：`a cute small factory building shaped like {阵营元素}， chimney with gentle smoke outline, front view, building only`
**地图底图**（重点：布局必须对齐代码常量）：

```
top-down cartoon battlefield map, horizontal dirt road across the middle,
a vertical blue river in the center crossed by a small wooden bridge,
green grass fields on both sides, soft clouds shadows, bright cheerful,
NO characters, NO buildings, NO text, 16:9
```

> ⚠️ 地图布局约束：代码常量 河道 x∈[-60,60]、主道 y∈[-45,45]、建造区左侧。AI 整图大概率画不准位置，**采用分层方案**：
> - 底层：AI 草地底图（只有草地+装饰，无路无河）；
> - 中层：道路、河道、桥**继续用现有程序色块绘制**（位置绝对准确），后续有精力再换成 AI 小贴图拼接。
> 这样美术效果立刻提升，又不引入"图和逻辑对不上"的 bug。

**UI 图标**：`flat game UI icon, golden coin / wave flag / crowd / sword / star, thick outline, candy colors, single object`（UI 单体图标 AI 很稳）

### 5.2 抠图

- 首选：即梦自带「智能抠图」；
- 备选：纯绿背景生成 → 醒图一键去底 / remove.bg；
- 进阶：Python `rembg` 库批量处理（同第 4 步脚本合并）。

### 5.3 批量后处理脚本（一次写好，全程复用）

用 Python + PIL 写一个 `tools/process_art.py`（放到仓库 tools 目录）：

1. 自动抠底（如需）；
2. 裁掉透明边缘（`getbbox`）、居中；
3. 等比缩放到接入尺寸（LANCZOS 高质量缩放）；
4. 按命名规范重命名输出到 `assets/resources/art/{分类}/`。

### 5.4 图集与压缩

- 每个分类目录建 Cocos「自动图集（Auto Atlas）」：units 一张 2048×2048、ui 一张 1024、fx 一张 512——同图集自动合批，draw call 少；
- 纹理压缩（构建发布时）：小游戏平台预设 **ETC2/ASTC + PNG 兜底**（微信 iOS 8.0.3+ 支持 ASTC；Cocos 引擎按设备自动挑选）；
- 地图底图 JPG 质量 80；所有 UI/精灵关 Mipmap；
- 包体红线：主包 ≤4MB（详见第 8 节预算）。

## 6. 动画方案（全程序 tween，零逐帧）

| 对象 | 状态 | 动画实现 | 参数建议 |
|---|---|---|---|
| 单位 | 待机 idle | sin 上下浮动 | ±3px，周期 2s，各单位随机相位（不整齐划一） |
| 单位 | 行走 walk | 弹跳 + 微倾 | ±2px @ 8Hz；左右摆 ±2°；速度越快频率越高 |
| 单位 | 攻击 attack | 朝目标 punch 位移 + 拉伸 | 前冲 6px（0.1s）弹回（0.15s）；scale.x 1.08 |
| 单位 | 受击 hit | 闪白 + 抖动 | 白闪 0.1s（已有）+ ±2px 抖 0.2s |
| 单位 | 死亡 death | 弹飞抛物线 + 旋转缩小 | 0.6s，旋转 720°，缩到 0；结尾星星粒子（已有） |
| 单位 | 出生 spawn | 弹性放大 | scale 0→1.2→1（elastic，0.3s），从工厂"蹦"出来 |
| 建筑 | 待机 | 顶部轻微起伏/旗子摆 | ±1px @ 0.5Hz |
| 建筑 | 被摧毁 | 碎裂粒子 + 下沉淡出 | 现有碎裂保留，加 0.3s 下沉 |
| 水晶 | 待机 | 呼吸缩放 + 光晕 | scale 1±2%，2s 周期；受击时抖动 + 屏幕震动（打击感核心） |
| 防御塔/光环塔 | 攻击 | 炮口后坐 | 后移 2px 弹回；弹丸已有 |
| 卡牌 | 出现 | 翻牌 | scale.x 0→1 + 上浮，0.2s，3 张错峰 50ms |
| 建造预览 | 放置成功 | 落地弹 + 尘土粒子 | scale 1.2→1（0.2s） |

实现提示：统一写一个 `UnitAnimator` 小工具（几十行），在 `syncUnits` 里按单位状态驱动，避免给 120 个单位各挂 tween（性能）。伪代码：

```ts
// 在 syncUnits 循环里按逻辑状态计算视觉偏移（无 Tween 对象，纯数学，最快）
node.y = u.y + bobOffset(u);          // 待机/行走弹跳
node.scale = attackPunch(u);          // 攻击瞬间
node.angle = walkTilt(u);             // 行走微倾
```

打击感三件套（验收"打击感到位"）：①受击白闪+抖动（已有基础）②击杀顿帧 0.05s（可选）③水晶受击屏幕震动（`gameContainer` 位置抖 0.2s）。

## 7. 工程接入方案

### 7.1 目录结构

```
assets/
  resources/            # 动态加载用
    art/
      units/            # 15 单位 + 3 大本营（自动图集 units）
      buildings/        # 工厂/学院/塔（自动图集可并入 units）
      ui/               # 面板/按钮/图标（自动图集 ui）
      fx/               # 特效贴图（自动图集 fx）
      map/map_bg.jpg
```

### 7.2 代码改造点（都在 GameManager.ts，改动可控）

| 现状 | 改造 |
|---|---|
| `makeEmojiVisual(emoji)` 色块+emoji | 新增 `makeSpriteVisual(path)`；emoji 保留为**资源缺失兜底** |
| `UNIT_EMOJI`/`FACTION_EMOJI` 映射 | 换成资源路径映射 `u_${faction}_${role}`、`hq_${faction}` |
| `onLoad` 一次性 `resources.loadAll` 预载图集 SpriteFrame，存 Map 缓存 | |
| `createColorNode` 特效体系 | 保留；`spawnEffect` 逐步支持传入 fx 贴图 |
| 血条 `attachHpBar` 程序绘制 | 保留（很轻，不用贴图） |
| `spawnFloatText` emoji/文字 | 保留（伤害数字/⭐ 用程序文字即可） |
| 敌我识别 | 脚底加红/蓝小色环（`createColorNode` 即可） |

### 7.3 验收方式

- 每完成一类资产跑一局 H5 预览（localhost:7456，记得标签页保持前台）；
- 对照检查表：风格统一？三阵营一眼可分？小尺寸下剪影清晰？色板符合？
- 小尺寸剪影检查技巧：把单位缩小到 24px 截图看剪影，认不出定位的图重做。

## 8. 包体与性能预算（主包 ≤4MB 红线）

| 项 | 预算 |
|---|---|
| 引擎+脚本（裁剪后） | ~1.5MB |
| units 图集（ETC2/ASTC 压缩后） | ~0.6MB |
| ui 图集 | ~0.3MB |
| 地图 JPG | ~0.25MB |
| fx 图集 | ~0.1MB |
| 首屏必需合计 | **~2.8MB ✅ 留有余量** |
| 卡牌面 27 张 + 音效 | **放分包**（分包合计上限另有额度）或远程 CDN |

性能守则：
- 同屏 120 单位 = 120 个 Sprite（同图集合批，draw call 个位数）；
- 单位贴图接入尺寸 128 已足够（显示最大 30px，4 倍余量）；
- 特效数量上限机制（弹道 120/特效 150/浮字 80）已存在，继续生效；
- 程序动画纯数学计算，无 Tween 对象池压力。

## 10. 合规与版权注意

1. **AI 内容标识**：按《人工智能生成合成内容标识办法》（2025-09-01 施行），上架含 AI 生成内容的游戏需注意平台的标识/申报要求；提审被问及时如实说明素材为 AI 辅助生成；
2. **AI 工具商用条款**：使用即梦等工具前确认其用户协议中生成内容的商用授权条款；保留提示词与生成记录备查；
3. **Kenney 素材**：CC0 协议，可商用、免署名；
4. **既有红线**：不出现魔兽相关角色/名称/图标/音效（沿用总纲第 14 节）；
5. **适龄**：维持全龄化表现（无血腥、死亡变星星）。

## 11. 风险与回退预案

| 风险 | 表现 | 回退动作 |
|---|---|---|
| AI 风格漂移 | 越生成越不像一个游戏 | 回到参考图法重新锚定；实在不行整体切 Kenney Tiny 系列+阵营染色 |
| 抠图边缘毛糙 | 白边/绿边 | 缩到接入尺寸通常可接受；个别图手动擦；提示词加 `no ground shadow` 预防 |
| 免费额度不足 | 每日积分用完 | 切换豆包/Leonardo 免费档轮着用；或冲刺期买一个月会员（约 ¥69） |
| 包体超 4MB | 构建报警 | 卡面/音频移分包；地图 JPG 降质量；units 图集 2048→1024 |
| AI 图过审问题 | 平台质疑素材来源 | 准备生成记录；必要时对关键素材人工重绘/替换 |
